# Model card: LightGBM speed forecaster

Generated by `scripts/train_lightgbm.py` from `models/metrics/lightgbm.json`. Do not edit by hand.

- **Model:** LightGBM, one direct global model per horizon (horizons 15 / 30 / 45 / 60 min), 207 METR-LA sensors.
- **Code version:** git `4124244 + uncommitted changes` (the commit the script ran on).
- **Training data:** 2012-03-01 00:00:00 → 2012-05-23 06:40:00. Validation 2012-05-23 06:45:00 → 2012-06-04 04:05:00 (early stopping and model selection). Test 2012-06-04 04:10:00 → 2012-06-27 23:55:00 (scored once).
- **Inputs:** the 39 point-in-time features for the horizon ([features.md](features.md)); missing values stay NaN.
- **Settings:** `{"objective": "l1", "learning_rate": 0.05, "feature_fraction": 0.8, "bagging_fraction": 0.8, "bagging_freq": 1, "max_bin": 255, "num_threads": 8, "seed": 0, "deterministic": true, "num_leaves": 127, "min_data_in_leaf": 500}`; early stopping on validation MAE, patience 100, max 6000 rounds.
- **Rounds:** h3 3540, h6 2906, h9 2291, h12 2192
- **Cost:** 60 min end to end on 8 CPU threads; peak memory not recorded (this run sampled memory only after each fit (950 MB); a separate timing run on full 60-min training data peaked at about 2.8 GB).

## Limits

- Trained on 12 weeks of spring 2012 traffic; no holidays, events or weather inputs.
- Point forecasts only: no prediction intervals yet.
- Accuracy drops sharply on congested targets; see the slice table.
- Not evaluated beyond the METR-LA network or after June 2012.
